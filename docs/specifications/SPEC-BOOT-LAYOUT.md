## Overview

The Boot Layout is the platform abstraction layer that resolves the workspace-local toolchain directory based on the host operating system. It provides:

1. **`ci_platform_name()`**, detects `linux` or `darwin` via `uname -s`
2. **`ci_boot_dir()`**, resolves the absolute path to `.boot-linux` or `.boot-macos` with legacy fallback
3. **`ci_boot_name()`**, returns just the directory name for marker checks
4. **`ci_relative_path()`**, pure-bash relative path computation replacing `realpath --relative-to`

**Implementation stack:** Pure bash functions in `projects/CI/lib/ci.sh`. Zero external dependencies. Inline platform detection for bootstrap scripts that cannot source `ci.sh`.

## Artifact Persistence

### Boot Directory Layout (per platform)

```
workspace/
├── .boot-linux/              ← Linux (gitignored)
│   ├── bin/                  ← uv, python, gitleaks, ...
│   └── python-env/           ← uv-managed Python venv
├── .boot-macos/              ← macOS (gitignored)
│   ├── bin/                  ← uv, python, gitleaks, ...
│   └── python-env/           ← uv-managed Python venv
├── .git/hooks/               ← GENERATED (platform-aware PATH)
└── projects/CI/lib/ci.sh     ← CORE (platform detection + boot resolver)
```

### Generated Hook Preamble

Every generated hook contains this platform-aware preamble (replaces hardcoded `.boot-linux`):

```bash
#!/usr/bin/env bash
# AUTO-GENERATED by projects/CI/scripts/generate-hooks, do not edit.
set -euo pipefail

_ROOT="$(git rev-parse --show-toplevel)"
cd "$_ROOT"
source "${_ROOT}/projects/CI/lib/ci.sh"
export PATH="${CI_BOOT_DIR}/python-env/bin:${CI_BOOT_DIR}/bin:$PATH"
```

## 1. Platform Detection API (`ci.sh`)

### 1.1 `ci_platform_name()`

```bash
ci_platform_name() {
    case "$(uname -s)" in
        Linux*)  echo "linux"  ;;
        Darwin*) echo "darwin" ;;
        *)       echo "linux"  ;;
    esac
}
```

| Property | Value |
|----------|-------|
| Input | None (reads `uname -s`) |
| Output | `linux` or `darwin` (lowercase, to stdout) |
| Side effects | None |
| External deps | `uname` (POSIX-mandated) |
| Bash version | 3.2+ compatible |

### 1.2 `ci_boot_dir([WORKSPACE_ROOT])`

```bash
ci_boot_dir() {
    local _root="${1:-${CI_WORKSPACE_ROOT:-$(pwd)}}"
    local _platform _preferred _fallback
    _platform="$(ci_platform_name)"
    _preferred="${_root}/.boot-${_platform}"
    _fallback="${_root}/.boot-linux"
    if [[ -d "$_preferred" ]]; then
        echo "$_preferred"
    elif [[ -d "$_fallback" ]]; then
        ci_warn "Legacy .boot-linux on $(_platform), consider re-bootstrapping"
        echo "$_fallback"
    else
        echo "$_preferred"
    fi
}
```

| Property | Value |
|----------|-------|
| Input | Optional workspace root path |
| Output | Absolute path to boot directory (to stdout) |
| Fallback | `.boot-linux` if platform dir missing |
| Warning | Emitted to stderr on legacy fallback (one-time) |
| Bash version | 3.2+ compatible |

### 1.3 `ci_boot_name()`

```bash
ci_boot_name() {
    echo ".boot-$(ci_platform_name)"
}
```

| Property | Value |
|----------|-------|
| Input | None |
| Output | `.boot-linux` or `.boot-macos` (to stdout) |
| Use case | Workspace marker checks (`[[ -d "$dir/$(ci_boot_name)" ]]`) |

### 1.4 Source-Time Variables

When `ci.sh` is sourced, the following variables are set:

```bash
CI_BOOT_DIR="$(ci_boot_dir)"      # absolute path
CI_BOOT_NAME="$(ci_boot_name)"    # directory name only
```

These are available to every consumer (generated hooks, CI scripts, compliance checks) without re-computation.

## 2. Portable Relative Path API (`ci.sh`)

### 2.1 `ci_relative_path(FROM_DIR, TO_DIR)`

Computes relative path using pure bash string manipulation (no external tools). Splits both paths on `/`, finds the common prefix, emits `../` for each remaining component in `FROM`, then appends remaining components from `TO`.

| from | to | result |
|------|----|--------|
| `/ws` | `/ws/projects/CI` | `projects/CI` |
| `/ws/projects/foo` | `/ws/projects/CI` | `../CI` |
| `/ws/projects/foo` | `/ws` | `../..` | source deeper than target |
| `/ws` | `/ws` | `.` |
| `/a/b/c` | `/x/y/z` | `../../../x/y/z` |

### 2.2 Replacement of `realpath --relative-to`

**Before** (`generate-hooks:47`):
```bash
_ci_rel="$(realpath --relative-to="$_repo_root" "$_CI_ROOT")"
```

**After:**
```bash
_ci_rel="$(ci_relative_path "$_repo_root" "$_CI_ROOT")"
```

All bootstrap scripts SHALL use this inline pattern (cannot source `ci.sh`):

## 5. CLI Wrappers

### 5.1 Portable `readlink -f` Replacement

**Before** (GNU-only, breaks on macOS):
```bash
SCRIPT_DIR="$(cd "$(dirname "$(readlink -f "${BASH_SOURCE[0]}")")" && pwd)"
```

**After** (POSIX-portable):
```bash
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
```

This works because CLI wrappers in `workspace/scripts/bin/` are invoked directly (not symlinked from elsewhere), so `dirname` alone suffices. If symlink resolution is needed, the portable alternative is:

```bash
SOURCE="${BASH_SOURCE[0]}"
while [ -h "$SOURCE" ]; do
    DIR="$(cd -P "$(dirname "$SOURCE")" && pwd)"
    SOURCE="$(readlink "$SOURCE")"
    [[ $SOURCE != /* ]] && SOURCE="$DIR/$SOURCE"
done
SCRIPT_DIR="$(cd -P "$(dirname "$SOURCE")" && pwd)"
```

### 5.2 Affected CLI Wrappers

| Script | `readlink -f` Line | `.boot-linux` Line |
|--------|--------------------|--------------------|
| `workspace/scripts/bin/repo` | Line 5 | Line 9: `BOOT_DIR="$AMI_ROOT/.boot-linux"` |
| `workspace/scripts/bin/run` | Line 5 | Line 11: `BOOT_DIR="$AMI_ROOT/.boot-linux"` |
| `workspace/scripts/bin/ops` | Line 5 | Line 11: `BOOT_DIR="$AMI_ROOT/.boot-linux"` |
| `workspace/scripts/bin/oc` | Line 3 | Line 10: `BOOT_DIR="${BOOT_LINUX_DIR:-${AMI_ROOT}/.boot-linux}"` |

### 5.3 Platform-Aware CLI Pattern

Each CLI wrapper replaces `readlink -f` with portable `cd + dirname` and uses inline platform detection for `BOOT_DIR` (same pattern as bootstrap scripts, see FR-6.3). The `BOOT_DIR` env var is honored as override.

## 10. Migration Path

### 10.1 Backward Compatibility

The migration SHALL be fully backward compatible:

1. **Linux unchanged:** `ci_boot_dir()` returns `.boot-linux`. No directory rename, no path changes.
2. **macOS new installs:** Returns `.boot-macos`. Bootstrap scripts create `.boot-macos/` with all tools.
3. **macOS legacy fallback:** If `.boot-macos` doesn't exist but `.boot-linux` does, returns `.boot-linux` with a warning.
4. **Environment variable override:** `BOOT_DIR` (new) and `BOOT_LINUX_DIR` (legacy) both work. `BOOT_DIR` takes precedence.
5. **Workspace detection:** Both markers accepted everywhere. No breakage for mixed environments.

### 10.2 Implementation Order

See [REQ-BOOT-LAYOUT Section 8 (Success Criteria)](../requirements/REQ-BOOT-LAYOUT.md#8-success-criteria) for the phase-by-phase implementation plan and validation checklist.

### 10.3 Validation Checklist

- [ ] `ci_platform_name()` returns `linux` on Linux, `darwin` on macOS
- [ ] `ci_boot_dir()` returns `.boot-linux` on Linux
- [ ] `ci_boot_dir()` returns `.boot-macos` on macOS (when dir exists)
- [ ] `ci_boot_dir()` falls back to `.boot-linux` on macOS (when `.boot-macos` missing)
- [ ] `ci_relative_path()` matches `realpath --relative-to` output for all test cases
- [ ] Generated hooks have correct PATH on both platforms
- [ ] `walk-projects` finds workspace root with either marker
- [ ] `make install-hooks` completes on macOS; generated pre-commit runs all checks
- [ ] `make install-hooks` completes on Linux (no regression)
- [ ] All modified files pass shellcheck, under 512 lines, no suppression directives
